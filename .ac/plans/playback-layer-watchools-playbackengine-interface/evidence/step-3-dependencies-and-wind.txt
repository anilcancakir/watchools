## Version solving: wakelock_plus had to move below its own latest

`wakelock_plus ^1.8.0` failed to resolve: 1.6.0+ raises its `win32` floor to
`^6.0.0`, and `magic` depends on `file_picker ^11.0.2`, which depends on
`win32 ^5.9.0`. 1.5.2 is the newest wakelock_plus version pub's solver
accepts against that floor, and it is the version `flutter pub get`
resolved with the overrides moved aside (the hosted-only committed lock).
1.5.2's own pubspec still declares a real macOS `pluginClass` and
`dartPluginClass` (`WakelockPlusMacosPlugin`), confirmed against the
resolved package under ~/.pub-cache: the plugin wraps `IOPMAssertionCreateWithName`
/ `IOPMAssertionRelease` directly, not a Dart-only stub.

## pubspec.lock discipline

`flutter pub get` was run TWICE, per CLAUDE.md's recipe:

1. `pubspec_overrides.yaml` moved to /tmp, `flutter pub get` run -> hosted-only
   lock. This is the one `git add`-ed. Diff against the previous committed
   lock is 39 insertions, nothing removed: `wakelock_plus` (1.5.2, direct main),
   its transitive `wakelock_plus_platform_interface` and `package_info_plus`/
   `package_info_plus_platform_interface`, and `watchools_player` (source: path,
   relative: true, version 0.0.1). `grep -c 'source: path' pubspec.lock` on
   this staged lock is 1: `watchools_player` only, which is the one legitimate
   path entry this step adds.
2. `pubspec_overrides.yaml` restored, `flutter pub get` run again for local
   development (this is what a contributor's next `pub get` produces anyway).
   That run resolves `wakelock_plus` to 1.8.0 and `win32` to 6.4.0, because the
   local `magic` and `fluttersdk_wind` checkouts solve differently than the
   published graph. This lock is LEFT UNSTAGED (`git status --porcelain
   pubspec.lock` shows `M pubspec.lock` in the working tree against the staged
   hosted-only version), matching the documented day-to-day behaviour.

## Two commands a human runs to finish it

1. In the Wind checkout, merge https://github.com/fluttersdk/wind/pull/203,
   then: `git tag 1.5.3 && git push origin 1.5.3` (the tag triggers
   `.github/workflows/publish.yml`, which runs `pub publish`).
2. In this repository, once 1.5.3 is on pub.dev: bump
   `fluttersdk_wind: ^1.5.0` to `fluttersdk_wind: ^1.5.3` in `pubspec.yaml`,
   then `flutter pub get` with the overrides moved aside and commit the
   resulting hosted-only lock.

Neither command was run by this step. `fluttersdk_wind: ^1.5.0` in this
repository's pubspec.yaml is untouched, per the Must Not.
