## 1. The lock, first, because that is the only moment it is still itself

A local `pub get` with `pubspec_overrides.yaml` active rewrites the lock with
sibling paths under /Users/, and every gate after `pub get` passes over such a
lock rather than failing on it. So this is measured against HEAD, which is what
CI clones.

  git show HEAD:pubspec.lock | grep -c 'source: path'   -> 1
  git show HEAD:pubspec.lock | grep -c 'relative: true' -> 1

EQUAL, which is what `.github/workflows/ci.yml:47-67` compares. Not zero, and
zero would be wrong: `watchools_player` lives under `packages/` in this
repository, so it is a legitimate path dependency and pub records it as
relative. The gate's own comment says exactly that.

The working tree reads 8 and 1, unstaged, which is the state `.gitignore`'s
regeneration recipe deliberately leaves behind.

Reading the printed hit/found matters here rather than only the percentage: lcov
carries only files the tests import, so the denominator moved when this plan
added `lib/app/playback/` and `lib/app/controllers/playback_controller.dart` to
it. It went from 2239 lines at the protocol layer's delivery to 2486 now, and the
ratio held because `FakePlaybackEngine` is a deliverable rather than a test
helper. That was decision D2's accepted cost and it did not come due.

## What no gate here covers, stated rather than implied

**No Swift is compiled by any of the above, and none is compiled by CI**:
`ci.yml:23` and `:150` both run `ubuntu-latest` and there is no
`flutter build macos` step. Step 4's whole deliverable is Swift, so it was
verified by a manual `flutter build macos --debug` during wave 2 (exit 0,
`Built build/macos/Build/Products/Debug/Watchools.app`). Any future step that
writes Swift needs the same manual build; a green CI says nothing about it.

**No gate here exercises real playback.** `flutter test` touches no engine, no
display and no provider. The macOS implementation's behaviour against a real
stream, the wakelock's effect on a real display, and the redaction of a real
FFmpeg reconnect warning are all unverified by this run.
