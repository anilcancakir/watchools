WHAT THE PLAN EXPECTED, AND WHAT ACTUALLY HAPPENED

The plan said the vault round trip would probably have to be recorded NOT RUN, because `.env.local` is
absent from this worktree and `ProviderSetupController.submit` stores only past a live panel handshake.

It ran in full. The repository ships its own Xtream panel (`tool/xtream-mock/`), so the walk went against
`http://127.0.0.1:3300` with the demo credential and cost the real subscription NOTHING. Zero requests
reached any real provider. The mock's log recorded 30 `player_api.php` requests, which is what proves the
app was reading a catalogue rather than the fixture.

SETUP

  $ node tool/xtream-mock/encode.mjs        # media/ was missing; ~4 s, gitignored, 48 MB
  $ node tool/xtream-mock/server.mjs        # http://127.0.0.1:3300
  $ curl .../player_api.php?username=demo&password=demo
    {"user_info":{...,"auth":1,"status":"Active","max_connections":"2",...}}

  $ ./bin/fsa start --device macos --vm-service-port 8199 \
      --flutter-arg=--dart-define=XTREAM_BASE_URL=http://127.0.0.1:3300 \
      --flutter-arg=--dart-define=XTREAM_USERNAME=demo \
      --flutter-arg=--dart-define=XTREAM_PASSWORD=demo
    flutter run pid=97209

  The defines reach the app through `XtreamCredentials.fromEnvironment`, which is debug-only and fires only
  when the Vault is empty. It was: `security find-generic-password` found no credential under
  `xtream_credentials`, `com.watchools.app` or that account name. Checked BEFORE starting the app, because
  a stored real credential would have made the launch fire a catalogue refresh at the user's own panel, and
  the standing instruction on that subscription is to spare it.

WHAT THIS WALK STILL CANNOT PROVE

The `paused` branch itself. macOS never delivers `AppLifecycleState.paused`
(`sky_engine/lib/ui/platform_dispatcher.dart:2444`) and no mobile target is wired, so no running app in this
repository can exercise it. The seven cases in `test/app/playback/mpv_playback_engine_test.dart` are the
entire assurance for that half, which is why step 2 was tiered `senior`.

The `hasCredential == false` branch was also not walked: reaching it would mean signing out of the mock,
which is a different screen state than the one under test here. It is covered by the widget test "is absent
when there is no credential to write to".
